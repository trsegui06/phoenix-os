# Purpose

Ce document définit les règles d'expérience utilisateur de Phoenix OS.

L'objectif est de garantir une interface cohérente, simple et orientée vers la prise de décision.

Chaque nouvel écran doit respecter ces principes.

---

# UX Philosophy

Phoenix OS n'est pas un tableau de bord.

Phoenix OS est un système de pilotage.

Chaque écran doit aider l'utilisateur à prendre une meilleure décision.

---

# Core Principles

## One Screen = One Decision

Chaque écran répond à une seule question.

Dashboard

→ Que dois-je faire aujourd'hui ?

Trading Day

→ Où en suis-je dans mon processus ?

Trade

→ Cette décision respecte-t-elle mon Playbook ?

Analytics

→ Suis-je en train de progresser ?

Settings

→ Comment fonctionne mon système ?

---

## One Card = One Information

Une carte ne présente qu'une seule idée.

Exemples :

Capital

Process Score

Mission

Coach

Checklist

---

## Information Hierarchy

L'utilisateur doit comprendre un écran en moins de cinq secondes.

Ordre de lecture :

1. Mission
2. État actuel
3. Action recommandée
4. Informations secondaires

---

## Calm Interface

L'interface doit réduire le stress.

Aucune animation inutile.

Aucun élément décoratif.

Chaque élément possède une fonction.

---

## Mobile First

Phoenix OS est conçu d'abord pour le téléphone.

Le desktop adapte ensuite cette expérience.

---

# Navigation

La navigation principale est située en bas de l'écran.

Modules :

Dashboard

Trading Day

Trades

Analytics

Settings

La navigation doit être accessible avec le pouce.

---

# Dashboard Rules

Le Dashboard est le cockpit.

Il ne montre que les informations utiles aujourd'hui.

Il ne présente jamais une liste complète de statistiques.

---

# Trading Day Rules

La journée suit toujours le même cycle.

Preparation

↓

Analysis

↓

Waiting

↓

Execution

↓

Review

↓

Close

Aucune étape ne peut être ignorée.

---

# Feedback

Chaque action doit produire un retour immédiat.

Exemples :

Checklist validée

Trade enregistré

Review terminée

Objectif atteint

---

# Error Prevention

Phoenix OS privilégie la prévention.

Exemples :

Avertissement avant dépassement du risque.

Rappel des règles du Playbook.

Validation obligatoire avant de commencer la session.

---

# Coach Phoenix

Le Coach n'est jamais culpabilisant.

Il :

observe ;

explique ;

recommande.

Il ne juge jamais.

---

# Accessibility

Contraste élevé.

Zones tactiles confortables.

Texte lisible.

Navigation simple.

Utilisable sans apprentissage.

---

# Product Experience

L'utilisateur doit ressentir :

Clarté.

Contrôle.

Confiance.

Discipline.

Calme.

---

# Success Criteria

Une personne découvrant Phoenix OS doit pouvoir :

comprendre l'écran en quelques secondes ;

savoir quoi faire ensuite ;

agir sans hésitation.

---

# UX Motto

Chaque écran.

Une décision.

Chaque décision.

Un progrès.
